**Branch:** `service/phase-9.2-serper-cost-reduction` (off `fix/rerun-findings`)
**Spec:** `docs/specs/2026-08-12-phase-9.2-enrichment-cost-reduction.md`

## What was done

Six commits, one per work item, in the sequence the spec specifies:

1. **`eb11501` — feat: account for every Serper call (WI-1).** New
   `shared/utils/serper-client.ts` is now the only place an outbound Serper request is
   issued from. It counts *attempts*, not calls — `fetchWithRetry` gained an
   `onAttempt` callback so a 429 retry is billed correctly instead of undercounted by
   up to 3×. Accounting is per-request (`AsyncLocalStorage`, opened by the route
   handler) and process-lifetime (`GET /api/debug/serper-usage`). Both production call
   sites migrated; `backend/scripts/tmp-serper-health.ts` (an unaccounted third
   spender) deleted; a grep-based test asserts no other file names
   `google.serper.dev`.
2. **`0e039ed` — fix: stop searching for reviews on domains that cannot be rendered
   (WI-2).** `UNRENDERABLE_DOMAINS` existed since Phase 9.1 but was only consulted in
   the fallback passes. The configured loop was still spending a full query-variant
   ladder on `klwines.com` for every wine before a render Phase 7 documented as
   permanently bot-blocked — guaranteed empty since the feature shipped. K&L stays in
   `RETAILER_CONFIG` (price/ needs it) and in `attemptedDomains` (the fallback passes
   still need to know it was never worth trying).
3. **`07fd9b5` — feat: tier retailer review sourcing into primary and extended passes
   (WI-3).** `RetailerConfig` gained `reviewTier: 'primary' | 'extended'`. The primary
   tier runs for every wine; the extended tier only escalates when the primary tier
   found no critic score, sharing the same `foundNoScore()` predicate the
   discovered-merchant and open-web passes already used. The per-retailer search body
   was extracted into one function both passes call. Tier seeding is explicitly
   provisional — labelled as such in `retailers.config.ts` — pending WI-7's real
   numbers.
4. **`470ded6` — feat: freshness guard and in-flight coalescing on enrichment routes
   (WI-4).** Both `/fetch-price` and `/fetch-reviews` take `?force=true`. Without it,
   data inside its TTL (price 7 days, reviews 30) returns as `{ ...wine, cached: true,
   fetched_at }` with no outbound call. A module-level `Map` in
   `backend/routes/enrichment-cache.ts` coalesces concurrent requests for the same
   wine+action, including the write. Frontend: `useEnrichmentAction` hook
   deduplicates what was previously separate busy/error state in `WineCard` and
   `WineDetailModal`; a cached response renders "Reviews updated 3 days ago" with a
   quiet "Refresh anyway" control.
5. **`3792e96` — feat: remember zero-result retailer probes per wine (WI-5).**
   Migration `004_phase9_2_probe_log.sql` adds `wines.review_probe_log`.
   `backend/modules/reviews/probe-log.ts` holds the one rule the feature exists to
   protect: skip a retailer only on a fresh `zero_results`, never on
   `no_relevant_match` (Phase 9.1 changed the ranking) or `request_failed` (the
   2026-08-05 data-loss conflation must not recur with a longer fuse).
   `fetchReviewData`'s return type stayed `ReviewResult[] | null` — the skip/write
   logic goes through `existingProbeLog`/`probeLogSink` options instead, so the ~90
   pre-existing assertions on the return value kept working unchanged.
6. **`6a32b0f` — feat: resolve fallback retailer product URLs on click (WI-6).**
   `resolveFallbackProductUrls` ran unconditionally inside `/fetch-price`, spending up
   to 5 Serper calls per price fetch on links most users never open. Removed;
   fallback retailers keep their constructed Google search URL. New
   `POST /:id/resolve-retailer-url` resolves one shop on click, persists it into
   `price_data.retailers[]`, and re-runs `aggregatePriceData` (holding `fetched_at` at
   its prior value, so resolving one link doesn't silently extend WI-4's price TTL).
   Frontend: `RetailerViewLink` opens a blank tab synchronously on click (never
   blocked, never trips a popup blocker) and points it at the resolved page or the
   original Google search after a 3s timeout, whichever comes first.

## Key decisions and rationale

- Every WI landed as its own commit, WI-1 first, matching the spec's stated
  commit sequence and its reasoning: nothing else in the phase is evaluable without a
  spend baseline.
- `UNRENDERABLE_DOMAINS`, `reviewTier`, and the probe-log's `zero_results` gate are
  kept as three separate mechanisms throughout, per CLAUDE.md §15 — a technical fact,
  a cost judgement, and a per-bottling memory are different reasons to skip a
  retailer, and collapsing them would produce config that lies about why.
- WI-5's design deliberately avoided widening `fetchReviewData`'s return type despite
  needing to surface new data (the probe log), because ~90 existing test assertions
  depend on `ReviewResult[] | null`. An options-based sink (`probeLogSink`) was judged
  cheaper and less risky than a signature change touched through the whole test file.
- WI-6's `fetched_at` handling is a decision not explicit in the spec text: reusing
  `aggregatePriceData` (which always stamps "now") to fix `nearest_retailer`'s
  stale-copy problem would have silently reset WI-4's 7-day price freshness on the
  strength of one URL resolution. Held `fetched_at` at its prior value instead,
  documented inline at the point of divergence.

## Bugs found and fixed

None in existing code — this phase was additive/structural, not a bugfix pass. One
internal near-miss avoided during implementation: initially wired `serperKey` as
possibly-`undefined` into the new tiered-pass helper functions inside
`fetchReviewData` (hoisted function declarations don't inherit the early-return
narrowing); caught by `tsc --noEmit`, fixed by re-binding to an explicitly-typed
`const apiKey: string` before the closures are defined.

## Testing

Cost-conscious throughout, as requested: all six work items are covered entirely by
mocked-network unit/integration tests (`jest` for backend, `vitest` for web) — nothing
in WI-1 through WI-6 spends a real Serper credit to develop or verify. New coverage:
`serper-client.test.ts`, `enrichment-cache.test.ts`, `probe-log.test.ts`,
`wines-resolve-retailer-url.test.ts`, plus new `describe` blocks inside
`reviews.test.ts` and `sqlite-adapter.test.ts`, and `EnrichmentFreshness.test.tsx` /
`RetailerViewLink.test.tsx` on the web side.

Final state: 402 backend tests (398 passing + 4 pre-existing skips), 70 web tests, all
green. `tsc --noEmit` clean in both `backend/` and `web/`.

## Addendum, 2026-08-15 — WI-7: live calibration re-run

Developer gave the go-ahead for the 14-wine re-run this same session. Two legs, as
the spec's WI-7 lays out.

### Leg 1a — untiered calibration probe

Extended `backend/scripts/validate-reviews.ts` with a per-retailer yield table
(wines searched / `zero_results` / `no_relevant_match` / pages found / scores from a
page whose producer+denomination+bottling were accepted *and* whose vintage gap is
exactly 0 / credits spent / scores-per-credit) and wired `getLifetimeUsage()` from
`shared/utils/serper-client.ts` into the script's own summary — it previously
imported nothing from the WI-1 accounting layer despite being the diagnostic script
for the module that layer instruments. Also added a `VALIDATE_SET=dry-run` mode (a
5-wine slice chosen to cover most of the fixture's `KNOWN_GOOD`/`KNOWN_BAD` cases) so
a sanity check could run before committing to the full batch's spend.

Ran the dry run first (108 credits, 5 wines) to confirm the yield-table code and the
matcher's live behavior before the full run — all three `KNOWN_BAD` traps in the
5-wine slice rejected correctly. Full batch: **387 Serper credits, 14 wines**, within
the 250–500 pre-run estimate. Full per-retailer table, the correctness cross-check
against `KNOWN_GOOD`/`KNOWN_BAD`, and the reassigned tier are recorded in the spec's
§3 — not duplicated here.

Headline finding: `benchmark` moved primary → extended. It carried real off-vintage
pages for several wines in the batch (`any-vintage` score count of 4 across the
batch) but zero right-producer-and-vintage hits, while costing 36 credits — tied for
the most expensive retailer in the configured loop. No promotions out of extended;
nothing there scored above zero in this batch. `jjbuckley` (0.276 scores/credit) and
`woodland` (0.226) are the clear primary-tier retailers; `flatiron` and
`winelibrary` are much weaker (0.034, 0.029) but still the best of the rest and
already primary, so left unchanged.

No regressions found against the 2026-08-11 DB snapshot — in fact the DB already
carried data closely matching today's live probe on most wines (same URLs, same
scores in several cases), which means Phase 9.1's fix has been holding continuously
in production, not just in this one measurement. One live-data-drift note, not a
code issue: a few `KNOWN_GOOD` cases (Benchmark/Charles Audoin, Morrell/Jean-Marc
Vincent) now resolve to a *different* retailer page than the fixture's pinned URL —
still correctly vintage-flagged, just a different bottling Serper surfaced today.
Retailer inventory moves; the matcher's verdict on whatever it finds does not.

One follow-up filed as a separate spawned task, not fixed in this branch (out of
WI-7's scope — matching/URL-shape logic is Phase 9.1's, not 9.2's): both the dry run
and the full run independently surfaced a `bid.zachys.com/language?url=...`
auction-lot redirect shape that slips past `isNonProductUrl`'s existing
`bid.zachys.com/auctions/...` patterns. It reached render + extraction (GPT-4o found
no score, so nothing wrong got stored this time) rather than being rejected at the
URL-shape gate the way the fixture's `bid.zachys.com/auctions/bidding-history/...`
case already is.

### Leg 1b — production tiered path

After reassigning `reviewTier`, started the real server and hit
`POST /:id/fetch-reviews?force=true` / `POST /:id/fetch-price?force=true` on 3 of the
14 wines (Bessin-Tremblay, Charles Audoin, Grand Village), reading
`GET /api/debug/serper-usage` before/after. Reviews: **28 credits for 3 wines**
(primary tier alone succeeded on all 3; `avoided: 72` confirms the 8 extended/
unrenderable retailers were correctly skipped, not silently omitted). Price:
**3 credits — exactly 1/wine**, confirming WI-6's fallback-URL removal held.
Re-hit `fetch-reviews` without `force` on the same wine: `{cached: true,
fetched_at}` returned, usage counter unchanged (31 → 31) — WI-4's near-zero
re-fetch claim confirmed against the real route.
