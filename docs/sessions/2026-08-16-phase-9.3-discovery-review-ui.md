### Phase 9.3 implementation

1. **WI-1 — Stop collecting `cellar_category` at creation.** Removed the select from
   `ScanResultCard`, `ScanEditForm`, and `AddWineForm`. All three `CreateWineInput`
   builders now send `cellar_category: null` unconditionally. Column/type left in place,
   documented as reserved in `docs/CLAUDE.md` (same treatment as `expert_reviews`).
2. **WI-2 through WI-6 — Discovery review screen.** One coupled commit — the
   `EnrichingCard` removal and the new screen's build touch the same files
   (`App.tsx`, `LabelScanFlow.tsx`) and aren't independently shippable:
   - `AddWineForm.onSubmit` and `LabelScanFlow.onSave` both now return the created
     `WineEntry`. `App.tsx` owns a new `reviewingWine` state that both creation paths
     resolve into, instead of `LabelScanFlow` managing its own "enriching" step.
   - New `web/src/components/DiscoveryReview.tsx` replaces `EnrichingCard` entirely.
     Built only on Phase 9.2's existing plumbing (`useEnrichmentAction`,
     `fetchWineReviews`/`fetchWinePrice`, `EnrichmentFreshness`, `PriceSection`,
     `CriticScoreBadges`) — no new route, no new Serper call site, no parallel cache.
   - Section order: identity → **Fetch Reviews** (click-gated, first and most
     prominent — never auto-fired, per Phase 9.2 §6's "enrichment stays
     user-initiated") → preferred-retailer carry-check → Price (unchanged
     auto-fetch-on-mount) → `tag_wishlist`/`tag_cellar` toggles (`tag_discovered` stays
     creation-default, not offered here) → Done.
   - New `web/src/utils/preferredRetailers.ts` (`summarizePreferredRetailers`) — a pure
     frontend function over the price fetch's existing `retailers[]`/
     `is_preferred_retailer`. Zero new Serper calls.
   - Label image dropped from both pre-save screens — `label_image_url` was already
     hardcoded `null` in every `CreateWineInput`, so nothing persisted was lost.
   - Retired "Wine-Searcher" copy/comments from `LabelScanFlow.tsx`, `WineCard.tsx`,
     `WineDetailModal.tsx` — pricing has been Serper-sourced since Phase 6.
3. **WI-7 — Tests.** 12 new tests for `DiscoveryReview` (identity render, reviews never
   auto-fetched on mount, price auto-fetch on/off, preferred-retailer summary's
   pre/post-resolution states, list-decision toggles restricted to wishlist/cellar,
   Done), 4 for `summarizePreferredRetailers`.

## Key decisions and rationale

- WI-2 through WI-6 landed as one commit rather than five, against the spec's suggested
  per-WI sequence — `EnrichingCard`'s removal and `DiscoveryReview`'s introduction are
  the same edit to the same files; splitting them would have meant an intermediate
  commit with no working post-scan screen at all.
- The preferred-retailer summary's "not shown before it resolves" behavior is tested
  with a manually-controlled promise (`act()`-wrapped resolution) rather than relying on
  synchronous assertions before an auto-resolving mock settles — the latter is racy and
  was the source of `act()` warnings during an earlier draft of the test file.
