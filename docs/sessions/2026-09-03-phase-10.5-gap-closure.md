## Key decisions

- **Scope is backend and frontend, not backend-only** — confirmed with the developer via
  `AskUserQuestion` before starting, since the gap doc's items span both and the request
  ("align the UI... to close the gaps between the two") implied both.
- **`wine_color` gets no provenance/`*_source` column.** Matches `quality_classification`'s
  existing precedent (a simple overwritable Tier 2 field), not
  `drinking_window_source`/`vintage_rating_source`'s manual-vs-derived tracking — nothing
  auto-derives `wine_color` on an ongoing basis, only a one-time label-scan extraction.
- **Cellar allocation grouped by `region`, not `appellation`.** The design-canvas mockup
  said "appellation chart"; `appellation` is a dead schema column (in `schema.sql`, never
  read or written by the adapter, per the Phase 6 note already on record) while `region`
  is `NOT NULL` and always populated. Corrected to match real data, same spirit as the
  rest of this phase.
- **`app_settings` is a new singleton table**, not an env var or a per-wine field — no
  existing settings/KV pattern in this codebase to extend, and DB-backed is consistent
  with everything else here (nothing else user-configurable lives in `.env` except API
  keys, per `CLAUDE.md` §6).

## Bugs found and fixed (not part of the gap doc, found along the way)

- **`backend/jest.config.ts`'s `testMatch` excluded `backend/db/` entirely.** Found while
  adding the new migration tests for `006`/`007` — `backend/db/migrate.test.ts` matched
  none of the three existing patterns (`__tests__/`, `tests/`, `modules/**`) and had
  therefore never actually run under `npm test` or CI, silently, since it was originally
  written. Fixed by adding a `db/**` pattern rather than moving the file.
- **`wine_color` being a required (non-optional) field on `CreateWineInput`** — same shape
  as every other Tier 2 field — meant every existing test fixture across both `backend/`
  and `web/` that builds a literal `CreateWineInput`/`WineEntry` needed a
  `wine_color: null` line added. Backend caught by `jest`/`ts-jest` (which does type-check
  test files); frontend caught by `tsc --noEmit` (web's `tsconfig.json` has no test-file
  `exclude`, unlike backend's). Worth remembering for the next new required field: it will
  surface the same way, in the same two places, for the same reason.
