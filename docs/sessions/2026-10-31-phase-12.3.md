## WI-4: no stored tiers, so no rewrite

The spec planned (a) a one-time rewrite of stored `match_tier` values. Checked first: the ladder is derived on every read from `review_data` and the wine's identity (`buildReviewLadder` in the SQLite adapter), and no tier is written anywhere. Read-only queries on the live database: 0 of 72 wines have `3a`/`3b`/`rung`/`tier` in `review_data`; `bottling_prompt_dismissed` holds modifier signatures (`vieilles vignes`, `albert bichot|…`), never a tier. So no migration. (b) still applies — a backend not restarted since the rename sends the old names — so the web maps them through `normalizeLadder` (`ladderOf` in `wineDerived.ts`) and iOS as it decodes (`LadderTier.normalize` in `ReviewLadder` / `ReviewLadderRung`). `CriticSummaryItem.rung` is not mapped on iOS: nothing on the phone reads it. (c) iOS fixtures regenerated; only `wine-bottling-prompt.json` and `wine-check-window.json` carry a tier, and the other twelve regenerated files differed only in ids and timestamps, so they were left as they were.
