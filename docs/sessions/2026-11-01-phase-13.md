## Bugs found

- `web`'s `build` script (`tsc && vite build`) emitted a `.js` beside every `.ts` in `web/src/` and `shared/`; ts-jest then loaded `shared/validation.js` and failed. Now `tsc --noEmit && vite build`.
- `db/migrate.ts` silently skips migrations when its `migrations/` directory is absent, so a compiled build that lacks the SQL files would boot against an unmigrated database with no error. The build's copy step now fails instead. `migrate.ts` itself is unchanged.

## WI-3, later the same session (built before WI-5, developer decision)

| Item | What |
|---|---|
| Backend | `backend/middleware/device-auth.ts`: `DEVICE_TOKENS` = `name:token,…`; bearer token on every `/api` route, constant-time; `res.locals.device`. `/healthz`, CORS preflights and the web bundle are open. Production refuses to start without tokens; locally, no tokens = no auth. `backend/middleware/metered-rate-limit.ts`: 60/hour, 200/day per device on label scan, tasting-note create, and the four wine enrichment POSTs; `429` + `Retry-After`; in memory. |
| Web | `web/src/access-key.ts` (`apiFetch`, which all 18 `api.ts` calls now use) attaches the key from `localStorage`; `AccessKeyGate` prompts after a 401 and drops a refused key; `vite.config.ts` can proxy to the cloud with `WINE_ACCESS_KEY` from `.env`, which never reaches the bundle. |
| Docs | CLAUDE.md §3/§6/§15, `.env.example`, spec "WI-3 as built", build-phases, runbook token section, and WI-5 steps now set a staging token. |

**Verified:** backend 795 and web 260 tests pass, with new tests for missing/wrong/revoked/malformed tokens, an open `/healthz`, preflight, each metered route capped per device, and the limiter's windows. In the browser, against the compiled server in production mode on localhost (test token, empty database): the prompt appears after the first 401, a wrong key gets "not accepted", and the right key loads the app (`/api` 401 → 200). A production start with no tokens exits before opening any database.

**Decisions:** `POST /api/tasting-notes` is rate-limited too (GPT tags), although the spec's list leaves it out. The static web bundle is not behind the token: a browser must load it to ask for the key, and it holds no secret. Limit counts live in memory and reset on idle stop; that is accepted, because the limit bounds damage per running hour and day and is not a ledger.

**Worth knowing:** Node 25 (the laptop) has a global `localStorage` stub that shadows jsdom's in Vitest, so the gate test supplies its own in-memory storage. CI's Node 20 is unaffected. The iOS app sends no token until WI-7, so phones can't use a token-protected backend before then; LAN debug is unchanged.
