## Bugs found

- `web`'s `build` script (`tsc && vite build`) emitted a `.js` beside every `.ts` in `web/src/` and `shared/`; ts-jest then loaded `shared/validation.js` and failed. Now `tsc --noEmit && vite build`.
- `db/migrate.ts` silently skips migrations when its `migrations/` directory is absent, so a compiled build that lacks the SQL files would boot against an unmigrated database with no error. The build's copy step now fails instead. `migrate.ts` itself is unchanged.

## Worth knowing

- **Exposure during WI-5.** Spec order puts WI-3 (device tokens) after the WI-5 gate. So the staging app answers anyone who finds its URL, and its metered routes spend the keys. The runbook says to keep it up only for the test and destroy it afterwards; the alternative is building WI-3's middleware first.
- **`fly.toml`'s `app` name is a placeholder** (`malolactic-wine`). Fly app names are global, so it may need changing when the production app is created.
- CI stays on Node 20 while the image is Node 22 (Puppeteer 25 needs ≥ 22.12). That is fine, because CI mocks Puppeteer.
- Your stash `stash@{0}` holds the pre-branch working-tree edits. The docs part is already on `main`, and the iOS part is committed here, so it can be dropped once you're satisfied.
