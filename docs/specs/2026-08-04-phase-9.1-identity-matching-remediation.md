## 1. Context in one paragraph

A 14-wine test batch on 2026-08-04 produced poor results. Investigation found that the
symptoms reported (missing reviews, dead shop links, few retailers) were surface
expressions of a deeper problem: **the four dimensions of wine identity — producer,
appellation, bottling, vintage — were each handled by a different mechanism in a
different module, and no code path evaluated all four.** The worst instance: nine
Château Lafleur critic scores (Decanter 100, Wine Advocate 99…) were stored against
Château Grand Village, a ~$30 wine, because the relevance check accepted any single
producer word found anywhere in a page's title *or body*, and the Lafleur page mentions
its sister estate. This phase closes that gap at the root rather than per-symptom.

An earlier remediation (2026-08-02) correctly identified logic duplication across the
three modules and deduplicated it into `shared/`. That fix held. The defects recurred
anyway — because duplication was the *mechanism*, not the cause. Do not re-run that
analysis; go straight to the work below.

## 2. Decisions already made — do not re-litigate

These were agreed with the developer on 2026-08-04. Treat as fixed requirements.

| Decision | Ruling |
|---|---|
| Wrong-vintage critic scores | **Keep and label.** Store with the page's own vintage and the gap in years. Exclude from `drinking_window`/`vintage_rating` derivation. The UI badges them ("2020 · 2 years earlier"), it does not hide them. |
| Vintage as a filter | **Never.** Vintage ranks candidates and labels results. It must not reject one. A shop whose only page for a wine is two vintages off should still yield that page. |
| Vintage tolerance threshold | **No hard-coded number in the pipeline.** The pipeline records the gap. A single display-layer constant (start at ±3) decides what renders as normal vs. flagged. Rationale: vintage variation is region-dependent, so any fixed threshold is a compromise — it should be advisory in display, not a hard rule in matching. |
| Matcher shape | **Graded, per-dimension** — not a tightened boolean. Already implemented, see §3. |
| Model-side check | **Yes, in addition** to the deterministic matcher. The GPT call should return *what wine the page is about*, not a yes/no verdict, so a rejection is debuggable. |
| Existing stored results | **Snapshot, purge, re-run.** Keep the current state as a "before" fixture. |
| Scope | Full set — correctness, coverage, empty states, and the regression suite. |

## 3. Already done — do not redo

`shared/utils/wine-match.ts` now exports a graded matcher. It is complete and covered by
32 passing tests in `backend/tests/unit/wine-match.test.ts`, every one built from a real
result in the 2026-08-04 batch.

```ts
export type Verdict = 'match' | 'mismatch' | 'unknown'

export interface MatchCandidate {
  title: string
  snippet?: string          // corroborating only — NOT consulted for producer
  url?: string
  statedVintage?: number | null   // e.g. GPT-extracted page vintage; wins over title parse
}

export interface MatchVerdict {
  producer: Verdict
  denomination: Verdict
  bottling: Verdict
  vintage: Verdict
  candidateVintage: number | null
  vintageGap: number | null       // |candidate − wine| in years
}

export function scoreMatch(candidate: MatchCandidate, wine: WineIdentity): MatchVerdict
export function isAcceptableMatch(v: MatchVerdict): boolean
export function compareByMatchQuality(a: MatchVerdict, b: MatchVerdict): number  // lower = better
export function extractVintage(text: string): number | null
export function foldDiacritics(s: string): string   // moved here from reviews/
```

Scoping rules, all deliberate:

- **producer** — title + URL only, and *every* significant word must be present. Snippet is
  excluded because body copy routinely name-drops other estates. This is the Lafleur fix.
- **denomination** — title + URL + snippet. Any one significant word confirms. Absence is
  `unknown`, never `mismatch` — we cannot prove a mismatch from silence.
- **bottling** — title + URL. `unknown` whenever the wine records no cuvee/vineyard/
  classification. All 14 batch wines are in that state, so this dimension is currently
  inert *by design*.
- **vintage** — recorded with the gap, used for ranking, never gates acceptance.

Token comparison is now whole-word, not substring. The old substring check let `vin`
(a significant word of "Vin de France") match inside "vintage".

`isRelevantMatch` is retained as a thin boolean wrapper so callers can migrate one at a
time. **Migrating them is WI-1 below** — the wrapper is a transition aid, not an endpoint.

## 4. Work items

Ordered. Each is one commit. Follow TDD per `CLAUDE.md` §11 — test first, then implementation.

### WI-1 — Migrate callers to `scoreMatch`, carry the verdict through

**Files:** `backend/modules/reviews/find-product-page.ts`, `backend/modules/reviews/index.ts`, `backend/modules/price/serper-query.ts`, `backend/modules/reviews/types.ts`, `shared/types.ts`

1. `find-product-page.ts` — replace `items.find(item => isRelevantMatch(...))` with:
   score every organic result via `scoreMatch({ title, snippet, url })`, filter to
   `isAcceptableMatch`, sort by `compareByMatchQuality`, take the first. **This is the fix
   that makes a shop indexing both the 2022 and the 2020 yield the 2022** — currently it
   takes whichever Serper happened to rank first. Return the winning `MatchVerdict`
   on `Step1Outcome`.
2. `serper-query.ts` — same treatment for the Shopping relevance filter. Derive
   `vintage_mismatch` and `matched_vintage` from the verdict rather than the local
   `extractYearFromTitle` (delete that function, use `extractVintage` from shared).
   Note the current `vintage_mismatch` computation fails open: `matched_vintage !== null && …`
   means an untitled year counts as a match. The verdict's `unknown` replaces that.
3. Extend `ReviewResult` (`reviews/types.ts`) and `RetailerReview` (`shared/types.ts`) with:
   ```ts
   page_vintage: number | null      // vintage the page itself states
   vintage_gap: number | null       // years from the wine's vintage; null if unknown
   match: MatchVerdict              // the verdict this result was accepted on
   ```
   `review_data` is a JSON column, so **no SQL migration is needed** — but update
   `backend/db/schema.sql`'s column comment and the storage adapter's round-trip test.

**Acceptance:** a wine whose only page at a shop is two vintages off is still stored, with
`vintage_gap: 2`. A Lafleur-shaped false positive is not stored at all.

### WI-2 — Stop discarding the extracted page vintage

**Files:** `backend/modules/reviews/index.ts`

`gpt-extract.ts` already returns `{ price, url, vintage, critic_scores }` and
`GptPageExtraction.vintage` is documented as in use. `renderAndExtract` passes it through.
`fetchReviewData` then reads only `extraction.critic_scores` and drops the rest.

Feed `extraction.vintage` back into `scoreMatch` as `statedVintage` for a **second, more
authoritative** verdict — the search-result title is a guess, the rendered page is
evidence — and store the result on `page_vintage`/`vintage_gap`.

**Acceptance:** Benchmark's Charles Audoin page stores `page_vintage: 2020`, `vintage_gap: 2`,
`match.vintage: 'mismatch'`. Its three scores remain in `review_data`.

### WI-3 — Gate derived fields on vintage-matched scores

**Files:** `backend/modules/reviews/derive-wine-level.ts`

`deriveWineLevelFields` currently flattens *all* scores across *all* retailers. Filter to
scores from results where `match.vintage === 'match'` before deriving `drinking_window`
and `vintage_rating`.

Also flag for the developer (do not change without asking): `pickSingleAgreeing` requires
unanimity — 0 values leaves the field alone, exactly 1 distinct value is used, 2+ distinct
values yield `null`. Mangot has 12 scores and derived `vintage_rating: 'very_good'` from a
single critic. **This rule gets worse as coverage improves.** It is out of scope here but
should be revisited before the UI depends on these fields.

### WI-4 — Fix the dead retailer links

**Files:** `backend/modules/price/index.ts`, `backend/modules/price/serper-query.ts`

Root cause: `price/index.ts:buildQuery` includes the vintage, and that same string is
handed to `buildRetailerSearchUrl`. When Serper matches a *different* vintage, the app
builds a link asking the shop for a year it doesn't stock. All six reported dead links
are this, exactly.

`retailer-links/index.ts` already made this call in Phase 7.2 — read its `buildQuery`
comment, it has a live-confirmed Zachys example. Mirror it here.

Split the two uses:

```ts
const searchQuery = buildDistinguishingQuery(wine, { includeVintage: true })   // → Serper
const linkQuery   = buildDistinguishingQuery(wine)                             // → constructed URL
```

Thread `linkQuery` through `querySerper` → `itemToRetailerResult` / `buildFallbackResult`.

**Acceptance:** for Bessin-Tremblay 2022, the stored Benchmark URL contains no `2022` token.
Add a test asserting no constructed retailer URL contains the vintage.

### WI-5 — Query-side: honorifics, diacritics, producer relaxation

**Files:** `shared/utils/wine-match.ts`, `backend/modules/reviews/find-product-page.ts`

1. **Diacritics.** `foldDiacritics` is now in `shared/`. Apply it inside
   `buildDistinguishingQuery` — it currently emits raw accents
   (`Gour%20de%20Chaul%C3%A9`, `Mangot%20Saint-%C3%89milion`), so the query is stricter
   about accents than the matcher it feeds. `find-product-page.ts` should import the
   shared one and delete its local copy.
2. **Honorifics.** `STOPWORDS` already knows `domaine`/`chateau`/`clos`/`maison` are noise —
   for matching only. The reviews query quotes the producer verbatim, so
   `"Domaine Jean-Marc Vincent"` fails against Morrell's "Jean-Marc Vincent". Add
   `stripHonorifics(producer)` and apply it when building quoted phrases.
   **Evidence this matters:** 7 of the 14 batch wines begin with "Domaine", and the price
   module found Morrell for Jean-Marc Vincent (correct vintage, $135) in the same run that
   the reviews module found nothing there.
3. **Producer relaxation.** `buildQueryVariants` relaxes cuvee/vineyard, then vintage —
   producer and denomination are never relaxed. Add an honorific-stripped producer variant
   *early* in the sequence, not last.

**Acceptance:** a test asserting `site:morrellwine.com` queries for Jean-Marc Vincent
produce a variant without the word "Domaine".

### WI-6 — Remove the Pass 1 short-circuit

**Files:** `backend/modules/price/serper-query.ts`

```ts
if (preferred.length > 0) return preferred   // ← delete this
```

One preferred-retailer match currently suppresses every other retailer. Grand Village
matched Zachys on a 2023 listing, which then failed the vintage filter and left

### WI-7 — Cross-feed the two modules

**Files:** `backend/routes/wines.ts` (router — modules must not import each other, `CLAUDE.md` §5)

Both directions are in the reported defects:

- Reviews found a live Woodland Hills product page for Mangot 2022 with 7 scores. Price
  returned **zero** retailers for the same wine in the same run. A confirmed product page
  is the strongest possible evidence a shop stocks a wine.
- Price discovered central-wine-merchants for Montus. Reviews only ever iterates
  `RETAILER_CONFIG`, so it never looked.

Have the router pass each module's discoveries to the other. Keep the coupling in the
router — do not add a cross-module import.

### WI-8 — Honest empty states

**Files:** `backend/modules/price/index.ts`, `backend/modules/price/verify-listing.ts`, `backend/modules/reviews/find-product-page.ts`, `shared/config/denylisted-domains.ts`

1. **K&L is added unconditionally.** `buildKlLinkOnlyResult` has no gate. Deleuze-Rochetin's
   entire retailer list is one K&L entry for a wine K&L doesn't stock. Second-order:
   because it's always appended, `allRetailers.length === 0` is unreachable, so
   `emptyPriceData()` never fires and the "attempted and found nothing" state — which the
   comment above it exists to preserve — has been destroyed. Gate it, restore reachability.
2. **Verification fails open.** `verifyStillListed` returns the retailer when the render
   fails; `pageShowsNoResults` is an eight-pattern English allowlist. Add a positive
   signal (does the page contain the producer name?) and surface render failure as an
   explicit `unverified` state rather than a silent pass.
3. **URL-shape guard.** Reject before spending a render + GPT call: `.pdf`, `/blogs/`,
   `/search`, `bid.`/`auction`, `/cart`. The batch already stored a JJ Buckley PDF
   (`2011_BORDEAUX_REPORT.pdf`), a Zachys auction bidding-history page, and two retailer
   blog posts as "product pages".
4. **Fallback hygiene.** Exclude domains already attempted this run and known-unrenderable
   ones — Bessin-Tremblay and Dureuil-Janthial both produced `fallback-shop-klwines-com`
   pointing at the identical URL that had just returned zero as a configured retailer, and
   K&L is documented as permanently bot-blocked. Add `wine-searcher.com` to the denylist.

## 6. Out of scope — do not do these

- **Label scan accuracy.** The batch has real upstream problems — `producer: "Montus"`
  (Château Montus), `denomination: "Vin de France"` for a Bordeaux Supérieur, and
  cuvee/vineyard null on all 14 while the products shops actually stock are named-vineyard
  1er Crus. Every module treats these as exact. This is real and worth its own phase, but
  the fix here is for the modules to *tolerate* imprecision, not for the scan to stop
  producing it.
- **`pickSingleAgreeing`'s unanimity rule.** Flagged in WI-3, needs a product decision first.
- **The ±3 display threshold.** Belongs with the UI build, not here.
- **K&L bot-detection evasion.** Explicitly out of bounds per `CLAUDE.md` §15.
