## 1. Goal

Make price and review enrichment **right when it answers, and honest when it doesn't**. Phase 9.1 and the Phase 12 device-testing fixes (PRs #37, #38, #40, #41, #44) made the matcher much better. The developer's 2026-10-04 test found the cases that are still wrong or silent. This phase works through them **evidence first**: replay each case against stored data for free, find the stage that failed, fix it in `shared/` or the owning module, and lock the case in as a regression fixture.

The developer's own framing of the biggest risk: *"it will be relatively common for there to be the same wine title with identifiers that make it more special."* A bare "Barolo" and a single-vineyard Barolo from the same producer are the typical case, and today the pipeline cannot tell them apart.

Items already fixed by PRs #36–#46 are **not** re-done here (developer instruction): legal-form and spacing matching, sibling appellations (Rosso vs Brunello), bottling-aware duplicate check, descriptor handling for Rioja-style tiers, magnum read from the product page on link resolve, the producer's own name no longer read as a bottle format, list reload after a scan's lookups land.

## 3. Lessons to build in (the "what can we learn" the developer asked for)

1. **Specificity matters in both directions (D8).** A wine that records no vineyard or cuvée is the plain bottling. A candidate that **adds** a naming word the wine never claimed (Monvigliero, Rocche, Vieilles Vignes) is evidence of a different bottling, and so is a candidate that **omits** a modifier the wine does record. Both are labelled and ranked, never silently matched; whether they feed the card depends on how healthy the exact-identity results are (D9).
2. **Descriptors are not universally generic.** PR #40 correctly made tiers like Gran Reserva / Riserva / Selección Especial *confirm but never reject*, because shops drop them. But "Vieilles Vignes" on a Châteauneuf is a separate cuvée at a different price. Whether a descriptor names a different wine is **region- and producer-dependent**; one global `GENERIC_BOTTLING_WORDS` list cannot encode that. The honest answer is "ambiguous", not a global yes/no.
3. **A wide price split means ambiguity, not outliers (D10).** The IQR fence assumes the majority is right. When counted per-750 ml prices span **2.5× or more**, drop nothing silently: refuse a single average, flag the wine as *possibly more than one bottling* and show both groups. The IQR fence stays for single-point outliers inside a narrower spread.
4. **Ask the user when ambiguity is detectable.** The candidates already carry the distinguishing words. If one producer + appellation + vintage yields several distinct extra names, ask "Which is yours?" with those names; the answer fills `cuvee`/`vineyard` and the pipeline **re-scores the stored candidates locally — no new Serper call**. This is the highest-value, lowest-cost fix.
5. **A lone listing is unchecked by definition.** The quartile fence needs ≥ 4 prices; the ratio fence needs ≥ 3. A single (or two) listing(s) driving the headline needs a *different* check — reading its product page (the #41 mechanism, local render, no Serper credit).
6. **Pack and size live on the product page, not the title.** Same root cause as #41, one level up: a title-only parser cannot see "Case of 6".
7. **A retailer is a registrable domain, not a host.** `nyc.` and `sf.` of the same shop carry the same ratings. Host-exact `site:` queries and host-exact matching silently drop half the shop.
8. **Silence must be explained.** "Found 5 listings, counted none" and "searched and found nothing" are different facts and must render differently (12.1 WI-4 is the client side; WI-1 below supplies the data).

### WI-1 — Price transparency from the backend

Add to `price_data` (JSON — no migration; read defensively, older blobs lack it):

```
excluded: { other_vintage: n, pack: n, non_standard_format: n, suspected_large_format: n, link_only: n, outlier: n }   // uncertain or unsupported formats only; suspected_large_format = a price-ratio flag whose page read stated no size (D11)
normalized: n                                   // listings counted via a ÷6 / ÷12 / ÷2 per-750 ml price
headline_basis: 'single_listing' | 'multiple' | 'ambiguous' | 'none'   // 'ambiguous' = counted prices span >= 2.5x (D10)
price_groups: [{ min, max, retailers: [slug…] }] | null                 // set only when headline_basis = 'ambiguous'; split at the largest adjacent price jump (proposed)
headline_estimated: boolean                     // true when a normalised listing drives the headline, min or max
```

computed inside `aggregatePriceData` from the same flags it already uses, including which listings the IQR fence dropped (`outlier`), so the client no longer re-derives them. 12.1 WI-4 renders it; until this lands 12.1 derives the same counts client-side.

**Decided 2026-10-05 (developer): normalise, don't just exclude.** When the system is **certain** a listing is a **six-pack, a 12-bottle case or a magnum (1.5 L)**, it divides the shelf price accordingly — **÷6, ÷12, ÷2** — to get the price of one 750 ml bottle, and that per-750 ml price is **counted** in min/avg/max. Rules:
- **Certain** means the format is stated outright in the *headline element or the product-title element* of the product page, or in the listing title Serper returned — e.g. "6 × 750 ml", "case of 12", "1.5 L", "magnum". A size-picker or body mention **never** counts (the #41 rule), and if two signals disagree the listing is **uncertain**. Uncertain → excluded and counted in the breakdown, exactly as today.
- **Only these three formats** are normalised. Half-bottles, 3 L and larger, 3-packs, gift sets and anything else stay excluded until the developer says otherwise.
- **Recorded on the listing**, not recomputed in the UI: `normalized: { kind: 'pack' | 'case' | 'magnum', divisor: 6 | 12 | 2, source: 'title' | 'page', shelf_price }`, plus `price_per_750`. `price` stays the shelf price. `aggregatePriceData` and both fences read `price_per_750` when `normalized` is set.
- **Shown honestly.** The retailer row carries a tag — "÷6 pack", "÷12 case", "÷2 magnum" — and shows both the shelf price and the per-bottle figure. When a normalised listing alone drives the headline, or sets the min or the max, the headline is marked **estimated** (`headline_estimated: true`) — because a magnum often carries a premium and a case a discount, so the division is an approximation, and the developer should see that.
- The exclusion breakdown still counts what was excluded; normalised listings are reported separately (`normalized: n`) so the sentence can say "1 six-pack counted at $117.83 a bottle".

**Acceptance:** Marcoux: the Benchmark six-pack ($707, 2019) counts at **$117.83** per bottle and the headline is marked estimated (a single normalised listing); the rest are listed as excluded with reasons (other vintages, link-only) — never a row of dashes. A listing whose format the page only mentions in a size picker is *not* normalised.

### WI-2 — Bottling ambiguity (the Vietti case)

1. **Detect, in both directions.** In the shared matcher, record for each accepted candidate `extra_names: string[]` (significant words in its title/URL that are not in the wine's identity, not the producer/appellation/vintage/format, not a tier word) **and** `missing_names: string[]` (cuvée/vineyard words the wine records that the candidate does not name). The GPT-4o page extraction additionally reports the modifier, cuvée or vineyard the page's wine bears (facts only, no verdict). Store all of it on the retailer/review result.
2. **Rank and label — never silently match, never silently drop (D8).** A candidate with extra or missing names ranks below an exact-identity one and carries a badge naming the difference in either direction ("Names Monvigliero — yours doesn't"; "Doesn't name Monvigliero — yours does"). Tier words stay lenient but labelled (D13). Only a name can still *reject* (`CLAUDE.md` §5 — unchanged).
3. **Reviews and retailer links: the ladder (D9).** Walk the rungs in order and stop at the first that yields a score: **T1** exact wine + same vintage + ≥ 1 trusted-critic score (WI-10 set, "same vintage" as WI-10 defines it); **T2** exact wine, other vintages, nearest first, stops at *any* score; **T3a** different bottling, same vintage; **T3b** different bottling, ±1–3 vintages. T1/T2 use only pages already returned or reachable by the page's own "other vintages" links (D12). T3a/T3b render and read the modifier-different candidates the existing queries already returned. Each result records `match_tier` (`'1' | '2' | '3a' | '3b' | 'none'`) and per-row `vintage_delta` and `bottling_difference`. The **drinking window / vintage rating** may draw on pages within ±3 vintages at any rung (labelled approximate, nearest vintage and highest rung preferred); a T2 page more than 3 years away is shown as that critic's reference window only, never merged into the derived window. Fixed rules decide; GPT-4o only reports page identity.
   - **Tier marker and explainer sheet (new, 2026-10-10).** The Critic reviews header on the detail card shows the tier in words — e.g. *"Matched at Tier 2 · same wine, other vintages ⓘ"*. The ⓘ is underlined and tappable (12.1 link rule) and opens a bottom sheet (iOS `.sheet` with detents; web: drawer) that says (a) what this tier means in one plain sentence, (b) what it does to the card badge and drinking window, (c) what was found at each rung that was tried (counts, critics, vintages), and (d) for T3a/T3b a **Which bottling is yours?** button. Rows below carry a year tag ("2019 · 2 yrs earlier") and, for T3, a "different bottling" tag. Tier 1 shows the marker too, in the quietest style ("Matched at Tier 1 · exact wine and vintage").
   - Tier copy (seed, Claude Code may tighten): T1 "We found a score for this exact wine and vintage from a critic we trust." T2 "No trusted score for this vintage, so we looked at other vintages of the same wine, nearest first. Scores and drinking windows from vintages within 3 years are used; further ones are shown for reference." T3a "We found nothing for this exact bottling, so we widened to a different bottling of the same producer and vintage (for example a named vineyard or special cuvée). Treat these scores as a guide." T3b "…and then to a different bottling from a nearby vintage (within 3 years). This is the loosest match we make."
4. **Price: all listings are counted; the gap rule decides (D10).** Order of operations: normalise certain packs/cases/magnums (WI-1) → drop vintage-mismatch and uncertain-format listings → **if the highest counted per-750 ml price is ≥ 2.5× the lowest, set `headline_basis = 'ambiguous'`, show no single min/avg/max, show both groups and drop nothing** → otherwise apply the existing IQR fence for genuine single-point outliers. Extra-name and missing-name listings are labelled but counted until the developer answers item 5.
5. **"Which bottling is yours?" — ask once per wine.** *Triggers* (any): ≥ 2 distinct modifiers appear in the results for the same producer + appellation + vintage; the price set trips the 2.5× rule (D10); review matching reaches T3a/T3b. It shows once; dismissing it ("Not sure") does not re-ask until a refresh brings new modifiers. *Presentation:* a non-blocking banner on the detail card ("Listings name different bottlings — which is yours?") that opens a bottom sheet. The sheet lists one row per modifier found, each with the evidence (retailers/critics that name it, count, price range) and underlined links to those pages, plus: **Plain / no special bottling**, **Something else** (text box with a Vineyard | Cuvée toggle), and **Not sure**. *On a choice:* write `cuvee` / `vineyard` (or the plain flag), **re-score all stored candidates locally (zero Serper calls)**, recompute the price headline from the matching set, re-run the ladder (a wine can climb back to T1/T2), and show a one-line result ("Now matched at Tier 1 — 3 trusted scores"). Non-matching candidates stay listed, labelled, outside the aggregates. An optional **Refresh with this bottling** button states its credit cost (`CLAUDE.md` §15) and is never automatic. *Edge cases:* check the new cuvée/vineyard against existing cellar rows (duplicate warning, WI-0 rules); "Plain" persists as a new nullable column `bottling_plain` (migration after 008/009; number assigned by Claude Code) so a later refresh does not re-ask; the choice is reversible from Edit; a typed name that matches nothing found keeps the wine at its current tier and says so. Rejections stay name-only.
6. **Descriptor leniency becomes data, not a global list.** Keep `GENERIC_BOTTLING_WORDS` for tiers (Rioja-style), which stay lenient **but labelled** when a listing omits or adds one (D13). Descriptors that commonly mark a *separate* cuvée (Vieilles Vignes, Cuvée, Prestige, Réserve de la Famille …) are **modifiers in both directions** (D8). Developer to review the short list before it ships (§8 Q3).
7. **Prompt the scan.** When the scan returns no vineyard/cuvée for a producer whose retailer results later show extra names, the draft review hints *"The label may name a vineyard or special bottling — check the bottle"* (PR #46 backlog item 2). Hint only; no blocking.

**Cost arithmetic (`CLAUDE.md` §15):** **zero new Serper calls.** Detection, ranking, clustering, the price-gap rule and re-scoring all run on already-fetched candidates. Step B (item 3) adds local page renders and one GPT-4o extraction per widened page, only when exact-identity results are not healthy; state the per-wine worst case in the PR.

**Acceptance:** Vietti Barolo 2021 (no cuvée, no vineyard). ### WI-3 — Pack and size for listings that drive the headline (Pavillon, Marcoux)

- **Product-page read for the headline-driving listing.** When the headline price comes from a single listing, or from the single listing that sets the min or the max, render its product page locally (no Serper credit) and run the existing `pageStatedFormat` plus a pack parser over the headline element and the product-title element — **never the body**, where size pickers list every format (the #41 rule). If it says a pack or a larger format, treat it exactly as the title parser would: normalise and count it if the format is certain (WI-1), otherwise flag and exclude.
- **Ratio fence for small sets (PR #46 backlog 1a) — a trigger, not a verdict (D11).** A listing at ≥ ~1.75× the median of ≥ 3 other same-vintage, same-format listings has its product page read (headline and title elements only; the cap of 2 page renders per fetch applies). If the page states a six-pack, case or magnum, normalise it per WI-1. If it states nothing, flag it *"price suggests a larger format or pack — size unconfirmed"*, count it under `excluded.suspected_large_format`, and keep it out of the average. It never applies to sets of < 4 comparable listings; those rely on the product-page read alone. This is a new check: the existing 5× `excludeExtremeOutliers` (other-vintage advisory range only) is unchanged.
- Record the flag source (`title` | `page` | `price_ratio`) so the UI can word it honestly.

**Cost:** local render time only; **0 Serper credits**. Budget one extra page render per headline-driving listing per fetch, capped at 2.

**Acceptance:** Pavillon Pommard 2019's Saratoga listing: if its product page states a six-pack, it counts at **$157.72** per 750 ml (÷6), tagged "÷6 pack", and the headline is marked estimated; if the page states nothing, the headline still rests on a single listing and the screen says so ("single listing — size not confirmed") instead of presenting $946.32 as certain.
