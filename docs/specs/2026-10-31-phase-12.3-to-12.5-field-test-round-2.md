## Phase 12.3 — Field-test round 2: label and display cleanups

**Status:** Not started. UI and one mechanical data rename. Web + iOS.

**Goal:** Remove noise the developer can infer for himself and fix labels, before touching matching logic.

**Deliverables:**

- **WI-1 — Hard refresh without credit figures.** Remove "about N credits" from Hard refresh on Reviews and on Price & retailers, web and iOS. Hard refresh still sends `force=true` and still clears the negative-probe memory. The iOS two-tap confirmation stays, and its text no longer quotes a figure. The credit constants stay in their file; they are just not rendered. Amend the 12.1 rule in `CLAUDE.md` ("states its credit cost").
  *Acceptance:* no string containing "credit" appears on either action row on either surface.
- **WI-2 — Labels.** "Find reviews" → "Trusted Retailers"; per-retailer button → "Search" (retailer name stays visible on its row). "from a different bottling?" → "from a different bottling" (tag text only; the banner question is handled in 12.5 WI-5).
  *Acceptance:* no "Find reviews" or "different bottling?" string left in `web/src` or `ios/`.
- **WI-3 — No year deltas.** Show the year only, never "N yrs earlier/later": critic vintage tab rows, the other-vintages band on wine detail, retailer and price rows. `vintage_delta` stays in the data (the tier logic and the display window use it); it is simply not rendered.
  *Acceptance:* no delta string renders on either surface.
- **WI-4 — Tier rename.** `match_tier` values `'3a'` → `'3'` and `'3b'` → `'4'` in `shared/types.ts`, backend, web, iOS, tests, fixtures and docs. Stored `review_data` JSON predates its types (Phase 12 lesson), so: (a) a one-time rewrite of stored `match_tier` values, (b) decoders on both frontends also accept the legacy `'3a'`/`'3b'` and map them, (c) iOS fixtures regenerated in the same PR (`export-ios-fixtures.ts`). Ladder order is unchanged. Copy: Tier 3 = different bottling, same vintage; Tier 4 = different bottling, nearby vintage.
  *Acceptance:* no `3a`/`3b` left in source outside the migration and the legacy-decoder test; a wine stored before the rewrite still decodes and shows Tier 3/4; docs (`CLAUDE.md`, `build-phases.md`, the 12.2 spec) use the new names.

**Rules carried forward:** no new metered calls; one definition, one place; scores and windows never blended.

**Milestone:** Nothing on the detail card asks the developer to do arithmetic or decode a tier name that isn't in the sequence 1–4.

## Phase 12.4 — Field-test round 2: matching, coverage and data fixes

**Status:** Not started. Backend-heavy, evidence-first, per 12.2 WI-0. Web + iOS wherever a result changes.

**Goal:** Fix what the 2026-10-31 notes show to be wrong or missing in the data, replaying each case from stored data for free before changing anything.

**Deliverables:**

- **WI-0 — Replay first.** Use `explain-wine` (12.2 WI-0), zero metered calls, on: Littorai Pinot Noir at Astor; 2019 Vieux Télégraphe La Crau at Kermit Lynch; Vieux Télégraphe blanc (11-year listing shown); Sansonet Saint-Émilion (2005 score shown); the magnum listing displayed as 12L; the wine that re-prompts for bottling. Add each as a red fixture in `ground-truth-wines.ts` first. Fixture URLs: Astor `https://www.astorwines.com/SearchResultsSingle.aspx?search=31372&searchtype=Contains` (tracking parameters trimmed); Kermit Lynch `https://shop.kermitlynch.com/product/detail/19FVT02`.
- **WI-1 — One similar-vintage window.** A single shared constant (`SIMILAR_VINTAGE_YEARS = 3`) used by critic rows, price listings, the retailer list and the tier ladder. Applied at display only; stored data and the pipeline are untouched. Remove the "reference window beyond 3 years" display from 12.2.
  *Acceptance:* Sansonet's 2005 score and Vieux Télégraphe blanc's 11-year listing no longer render; a listing exactly 3 years away renders and one 4 years away does not; a wine whose only data is outside the window shows the "nothing found" state, never a blank area.
- **WI-2 — Why Kermit Lynch and Astor are missing from the price and retailer list.** These two are **price, availability and link retailers only**: neither publishes critic reviews, so neither belongs in review sourcing (developer, 2026-10-31). If they are added to `shared/config/retailers.config.ts`, config needs a way to say so (today `reviewTier` allows only `primary | extended`; add `'none'`) so the review loop never spends a call on them. The developer's evidence: Google's first result for the 2019 La Crau is Kermit Lynch's own product page (`https://shop.kermitlynch.com/product/detail/19FVT02`), yet the widget omitted it. A first organic result is not the same as a Google Shopping result, and price discovery is a single Serper *Shopping* call filtered by retailer, so find the stage that dropped it before building anything. Do not assume a cause: find the stage with evidence, report it, then change code. Steps:
  0. **Check config:** is Kermit Lynch (and Astor) in `shared/config/retailers.config.ts`, with what `matchKeyword`, domain and search-URL pattern? Note whether the retailer-links module lists them.
  Then replay with `explain-wine` from stored `price_data` (zero calls). If the stored data does not keep the raw Serper Shopping titles and URLs, run **one** `--live` Shopping query for this wine (about 1 Serper credit; print the estimate first) and record the raw results. Check, in this order:
  1. **Not in the Shopping response at all:** Shopping lists only merchants that submit product feeds. The developer doubts this is the cause, so verify it from the raw response rather than assuming it.
  2. **In the response but cut:** the Pass 2 merge caps at 8, or the matcher labelled it a different bottling or rejected it on a name.
  3. **Dropped by the live listing check:** `verify-listing.ts` renders the shop's own search URL, which is an unverified generic `/search?q=` guess for any retailer not in the explicit switch, and is exposed to the `domcontentloaded` timing gap.
  4. **Kept but not counted:** vintage unknown, or stored as link-only.
  If it is cause 1, the options are: **(a)** discover price for configured price-only retailers through a `site:`-restricted organic search, then render the product page and extract the price (the Phase 7.2 confirm-retailer-link path). *Arithmetic:* +1 Serper credit per such retailer per wine, plus a render and a GPT-4o call; and the 7.2 known gap (windowing drops price text) must be fixed first. **(b)** list them under Trusted Retailers as Search links with no price: 0 credits, and no price in the widget. Developer chooses. Either way, a new retailer needs a search-URL pattern **verified with a live Puppeteer render** (the Phase 7.3 caveat).
  *Acceptance:* the replay output names the stage that dropped the 2019 La Crau at Kermit Lynch, with a fixture; after the fix, that row appears (priced, or as a link under Trusted Retailers if option b) tagged exact vintage; the same check is run for Littorai Pinot Noir at Astor; neither retailer triggers any review-sourcing call.
- **WI-3 — Retailer order.** Nearest first, then the other preferred (configured) retailers alphabetically, then non-preferred listings alphabetically, only those within the window. One comparator, computed once (backend), used by web and iOS.
  *Acceptance:* the La Crau list renders nearest → preferred A–Z → others A–Z on both surfaces.
- **WI-4 — Bottling answer sticks.** Diagnose, then fix. Working hypothesis, to verify in the replay: the banner's triggers (≥ 2 distinct modifiers, the 2.5× price split, or Tier 3/4) are re-evaluated against stored results on every render, so an answer that re-scores locally still leaves them true and the sheet re-opens. Fix: an answered state. Once the developer picks *Plain*, a named bottling, or *Something else*, the banner does not return until Edit changes the bottling or a refresh brings a modifier not seen at answer time. The wine then shows a quiet "Bottling: X · Change" row. "Not sure" keeps its existing no-re-ask rule.
  *Acceptance:* pick an entry → sheet closes, banner gone → reopen the app → still gone → the chosen bottling is shown with a Change action → a normal Refresh does not re-ask → zero Serper calls from answering. Same on web.
- **WI-5 — 1.5L shown as 12L.** Locate where the size is parsed or mapped (suspects: the named-format table in `pack-format.ts`, a "12 × 750 ml" case read, the ÷2 magnum normalisation tag). Fix and fixture.
  *Acceptance:* a 1.5L listing displays "1.5L"; a real Balthazar still reads 12L; the producer-name blanking from the 2026-10-04 fix is unaffected.
- **WI-6 — Wine colour for imported wines.** *Needs your decision, see below.* Where `wine_color` is null on a wine that did not come from a label scan, infer it from grape varieties, region, appellation and producer with one batched, text-only GPT-4o call; allow `null` when ambiguous. Mark the value as derived using the existing `*_source` convention so the Sourced marker applies; a manual value is never overwritten. Ship a **dry run first** that prints proposed values for review before anything is written. The same step covers future sheet/CSV imports. The scan path is unchanged (vision only).
  *Arithmetic:* about one GPT-4o text call per 20 wines — roughly 4 calls for 78 wines, once — and 0 Serper credits.
  *Acceptance:* after the backfill every imported wine has a colour or an explicit null with its reason in the dry-run output; a manually set colour is untouched; Cellar red/white/rosé split is populated for the imported wines.
- **WI-7 — "Failed" versus "nothing found".** The backend already separates `request_failed` from `zero_results` in the probe log. Expose one explicit `outcome` on each price and review result (`found`, `none_found`, `none_counted`, `failed`) and trace why a search that ran and found nothing currently reads as a failed lookup.
  *Acceptance:* a search that ran and returned no relevant listing reports `none_found` and never `failed`; `failed` appears only for errors and timeouts.

**Rules carried forward:** replay before fixing; vintage ranks and labels in the pipeline and never rejects there; only a name can reject a bottling; never blend across sources; manual values win; each migration file runs once.

**Milestone:** The cases from the 2026-10-31 test either return the right data or state on screen why they didn't, and the retailers the developer actually shops at are searched.

## Phase 12.5 — Field-test round 2: price and critic redesign, copy pass

**Status:** Not started. Depends on 12.4 WI-1, WI-2 and WI-7. Web + iOS.

**Goal:** Make the price and critic blocks readable at a glance on a phone, and cut the app's copy to what a reader needs.

**Deliverables:**

- **WI-1 — Price state model.** One state per wine, computed once in the backend (`price_state`, same pattern as `window_status`) and rendered identically by both clients. One line each; no breakdown sentences.

  | State | When | Line | Below it |
  |---|---|---|---|
  | Looking | In progress | "Checking prices…" | — |
  | Priced | ≥ 1 counted, in-window, same-vintage listing | **$85 avg**, range $70–$110, **Exact match** badge | Retailer links |
  | Estimated | Headline relies on a normalised pack or magnum | **$85 avg · est.** | Retailer links |
  | Wide range | Counted prices span ≥ 2.5× (`headline_basis = 'ambiguous'`) | "Prices vary widely" | Both groups; "Which bottling?" |
  | Similar vintages | Prices exist only for other vintages within ±3 | "Similar vintages" | Links, each tagged with its year |
  | No average | Listings found, none countable | "Prices found, no average" | In-window links with prices |
  | Nothing found | Search ran, no in-window listing | "No prices found" | Trusted Retailers |
  | Failed | Error or timeout (`outcome = failed`) | "Couldn't check prices" | Retry, neutral style |

  Gigondas example: the 2022 listing is out of window and drops away; the 1 search-only link moves to Trusted Retailers; the line reads "Prices found, no average" or, if nothing else remains, "No prices found".
  *Acceptance:* each state has a fixture and renders the same line on web and iOS; no price block contains the words "listings", "counted" or "none counted toward".
- **WI-2 — Trusted Retailers is the only home for search links.** The price list shows priced listings only, ordered per 12.4 WI-3. Search-only and link-only entries appear under Trusted Retailers.
- **WI-3 — Critic reviews declutter.** Header: the tier as one short line with the ⓘ (Tier 1 shows the badge instead). Every score stays visible — **no collapse or disclosure** (developer, 2026-10-31). Order: trusted-critic scores first, same vintage first (12.1 WI-10). The declutter comes from the rows themselves: one compact line per score (critic, score, year), no deltas, no per-row explanation, and a "different bottling" tag on Tier 3/4 rows only. Explainer sheet bodies cut to one sentence plus the counts.
  *Acceptance:* on the Aloxe-Corton critics screen, an iPhone 17 Pro at default Dynamic Type shows the tier line plus at least the first three scores without scrolling; every score the wine has is present on the screen; no row wraps to a second line at default size unless the critic name is unusually long.
- **WI-4 — Exact match badge.** A small "Exact match" badge wherever the match is exact wine and exact vintage: the critic header at Tier 1, and each retailer row whose listing is exact identity and same vintage. No badge at any other tier.
- **WI-5 — Copy audit.** Step 1: Claude Code extracts every user-facing string from `web/src` and `ios/` into one table (file, current text, surface). Step 2: Claude proposes a shortened string for each, against the rule *one short sentence; an explanation only behind a tap*. Step 3: the developer vetoes or edits, and only then are strings changed. The seed list below is drawn from the specs and is not exhaustive.

  | Where | Now | Proposed |

  | Bottling banner | "Listings name different bottlings — which is yours?" | "Different bottlings found. Which is yours?" |
  | Critics screen hint | "The label may name a vineyard or special bottling — check the bottle" | Remove (the banner already asks) |
  | Draft review hint | same hint | "Check the bottle for a vineyard or cuvée." |
  | Hard refresh | "Hard refresh · about N credits" | "Hard refresh" |
  | Tier 1 marker | "Matched at Tier 1 · exact wine and vintage" | Badge: "Exact match" |
  | Tier 2 marker | "Matched at Tier 2 · same wine, other vintages" | "Tier 2 · other vintages" |
  | Tier 3 / 4 marker | (3a / 3b copy) | "Tier 3 · different bottling" / "Tier 4 · different bottling, other vintage" |
  | Price breakdown | "2 listings found, none counted toward the average: 1 other vintage (2022), 1 search only" | "Prices found, no average" |
  | Empty price | "No matching listings found" | "No prices found" |
  | Unverified badge | long explanation | "Couldn't confirm. Price may be outdated." |
  | Verified badge | long explanation | "Shop page mentions this producer." |
  | Search-only badge | long explanation | "Search link, no price." |
  | Oversize price | "price suggests larger format — size unconfirmed" | "Size unconfirmed" |
- **WI-6 — Docs.** `CLAUDE.md` (Hard refresh rule, tier names, similar-vintage display rule, colour inference amendment), `build-phases.md` (these entries), the 12.1 and 12.2 specs amended at the original claims, session note.

**Rules carried forward:** enrichment results never silently disappear; every state is explicit; every tappable link underlined; scores never blended.

**Milestone:** The price and critic blocks answer "what does it cost and who says it's good" in a few lines each, with nothing on screen the developer has to read twice.
